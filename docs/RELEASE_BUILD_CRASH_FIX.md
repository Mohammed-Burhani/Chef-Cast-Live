# Release-Build Crash Fix — "App opens then crashes" (expo-av → NoClassDefFoundError)

> Reference for AI agents (or humans) working on this repo. This documents the
> exact root cause and fix for the release-build startup crash ("app has bug" /
> "keeps stopping" dialog), the diagnostic method used to find it, and the build
> environment gotchas that matter. Applies to both `./gradlew app:assembleRelease`
> and EAS builds.

---

## TL;DR

**Root cause:** `expo-av@16.0.8` — a dependency the app **never imports** — shipped a
native module (`VideoViewModule`) that references `expo.modules.kotlin.types.LazyKType`,
a class that does **not exist** in the installed `expo-modules-core@56.0.15`. Expo's
autolinking compiles every native module in `node_modules`, so ReactHost registration
threw a `NoClassDefFoundError` during native init and the app died **before JS ever
loaded** — only in release/EAS builds, not in Expo Go.

**Fix:** `bun remove expo-av` (zero references anywhere in `app/`, `components/`, `lib/`).
Verified by rebuilding the release APK and launching on an emulator.

## The crash

| Symptom | Detail |
|---|---|
| Dialog | "Foodilicious keeps stopping" / "app has bug" — appears a moment after the icon |
| When | Only in release/EAS builds (`assembleRelease`, `eas build`). Never in Expo Go |
| Timing | During native init (TurboModuleManager) — before React/JS loads |
| Logcat | `java.lang.NoClassDefFoundError: Failed resolution of: Lexpo/modules/kotlin/types/LazyKType;` at `expo.modules.av.video.VideoViewModule.definition(VideoViewModule.kt:118)` |

### Why it "works locally" but crashes in release

- **Expo Go** bundles its own precompiled, mutually-compatible native modules (its
  own expo-av + expo-modules-core pair). The app's JS never imported `expo-av`, so
  nothing surfaced in dev.
- A **release build** compiles the project's actual `node_modules`. expo-av's native
  AAR was built against a newer expo-modules-core that contains `LazyKType`; the
  installed expo-modules-core 56.0.15 does not. Autolinking registers
  `VideoViewModule` regardless of whether JS uses it → crash.

### Why the usual suspects were ruled out

- **Reanimated 4.3.1 / react-native-worklets 0.8.3** — the 
  `react-native-reanimated/plugin` in `babel.config.js` is a shim that re-exports
  `react-native-worklets/plugin`. Probing the compiled bundle showed `useMemoCache=0`
  on every Reanimated file and both `libreanimated.so` + `libworklets.so` present in
  the APK for all ABIs.
- **React Compiler** (`experiments.reactCompiler: true` in `app.json`) — probe showed
  it never processes Reanimated files, and disabling it changed nothing.
- **Hermes bytecode** — confirmed present with correct magic header.
- **R8/minification** — `minifyEnabled` is `false` by default in this project.
- **`inlineRequires`** — Metro's production default is `false` here; not the cause.

The decisive evidence was the logcat stack pointing at a **native module class
mismatch**, which is the classic signature of an unused-but-autolinked module compiled
against a mismatched core version.

---

## The fix (exact)

```bash
bun remove expo-av
```

That removed one line from `package.json` and the corresponding entries in `bun.lock`.
No source code changes were needed — `expo-av` had zero imports in the codebase and
was not referenced in `app.json` plugins. If a dependency is ever re-added, verify it
has no native module incompatible with `expo-modules-core@56`.

`com.foodilicious.live/.MainActivity`, JS bundle loaded (`Running "main"`), and the

## Environment facts & gotchas (read before building)

- **SDK / toolchain:** Expo SDK 56, React Native 0.85, Hermes, New Architecture
  (`newArchEnabled=true`). TypeScript ~6.0.3.
- **`android/` is gitignored** (generated by `expo prebuild`). Do not hand-edit it;
  regenerate with `npx expo prebuild --clean --no-install` after `app.json` changes.
  There is no `ios/` in this repo (Windows host).
- **JDK:** `java` on PATH is JDK 8, but **Gradle needs JDK 17** — set `JAVA_HOME` to a
  JDK 17 before running Gradle, otherwise the build fails.
- **Emulator AVD `chefcast_test`:** needs `hw.cpu.arch=x86_64` (+ `hw.cpu.ncore=4`) in
  `C:\Users\raj_1\.android\avd\chefcast_test.avd\config.ini`, or it panics with
  "CPU Architecture 'arm'". Uses **WHPX** (Windows Hypervisor Platform) acceleration.
- **Release signing** uses the debug keystore (default prebuild config) — fine for
  testing, not for store upload.
- **App identity (current):** display name `Foodilicious`, package/bundle id
  `com.foodilicious.live`, scheme `foodilicious`, EAS project id
  `8d89f8a4-3aba-40db-b6d5-f81caa4e3e28`.

## Related: Firebase / push (why the build now includes google-services.json)

The release APK is now built with Android **Firebase Cloud Messaging** so
`expo-notifications` can mint an Expo push token (required for remote push on
Android — there is no non-FCM path for a standalone Android build). Relevant to
"did this build crash":

- `app.json` → `android.googleServicesFile: "./google-services.json"`; the
  `expo-notifications` config plugin applies the `com.google.gms.google-services`
  Gradle plugin when this is set.
- `google-services.json` `package_name` **must exactly equal** `android.package` in
  `app.json` (`com.foodilicious.live`). A mismatch fails the **build** (not a runtime
  crash) with "No matching client found for package name …".
- `bun install` / lockfile: keep `expo-av` absent; the only past startup crash was
  native-module version skew, so watch `expo-*` core-version pairing after upgrades.

Full push/email flow documentation lives in `docs/PUSH_NOTIFICATIONS.md`.

## Quick re-verification checklist for a future AI

1. Confirm `expo-av` is **not** in `package.json`.
2. Confirm `google-services.json` exists and its `package_name` matches
   `app.json` `android.package`.
3. `npx expo prebuild --clean --no-install` → `cd android && ./gradlew app:assembleRelease`
   → install → launch → logcat shows no `FATAL EXCEPTION`.
4. If a new crash appears, pull `adb logcat -d | grep -iE "fatal|androidruntime"` first —
   native-module `NoClassDefFoundError` is the signature to look for.
